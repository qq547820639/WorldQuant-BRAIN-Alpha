# BRAIN Alpha Ops — 用户体验架构 v2.0

> **目标**：消除用户流程中的 7 个断点，建立引导式工作流体验
>
> **日期**：2026-06-08 · User Experience Architect

---

## 一、当前断点分析

通过四种用户场景的旅程追踪，识别出以下断点：

| # | 断点 | 严重度 | 用户影响 |
|---|------|--------|---------|
| B1 | **JobMonitor 仅在 Dashboard 可见** | 🔴 致命 | 运行时导航到其他页面→进度完全丢失，后端仍在运行但用户盲飞 |
| B2 | **selectedCandidate 导航时被清空** | 🔴 致命 | 从评分页切回候选管理→忘记在看哪个候选 |
| B3 | **侧边栏顺序与工作流不匹配** | 🟠 重要 | 用户需扫描 10 个条目找到下一步，无引导 |
| B4 | **无面包屑/返回导航** | 🟠 重要 | 在深层页面（评分）无法一步返回，必须侧边栏点击 |
| B5 | **凭证面板仅 Dashboard 可见** | 🟡 中等 | 在其他页面修改凭证需回到首页 |
| B6 | **10 个平铺条目无优先级区分** | 🟡 中等 | "工作流程"和"工具"标签弱区分，用户感知为一整块 |
| B7 | **无跨页面状态持久化** | 🔴 致命 | JobMonitor 本地 state 在 unmount 时销毁，SSE 连接断开 |

## 二、优化方案：三层信息架构

### 设计原则

1. **状态永不离身** — 运行中任务的进度在任何页面都可见
2. **流程即导航** — 侧边栏反映工作流顺序，自动高亮当前步骤
3. **上下文不丢失** — 选中项、运行状态跨页面保持
4. **最少点击原则** — 常用操作零跳转，深层操作一键返回

### 架构总览

```
┌─────────────────────────────────────────────────────────┐
│ TOP BAR · 面包屑 + 连接状态 + 运行中任务 minibar        │
├──────┬──────────────────────────────────────────────────┤
│      │                                                  │
│ S    │   凭证面板（可折叠）                              │
│ I    │                                                  │
│ D    │   [运行中任务 minibar] — 始终可见                 │
│ E    │                                                  │
│ B    │   主内容区                                        │
│ A    │   · Dashboard / 候选 / 评分 / 质量 / ...         │
│ R    │                                                  │
│      │                                                  │
├──────┴──────────────────────────────────────────────────┤
│ STATUS BAR · 环境 · 版本 · 非提交提示                    │
└─────────────────────────────────────────────────────────┘
```

## 三、核心改进设计

### 3.1 侧边栏重排序 — 工作流引导

**当前顺序**（字母/编号排序）:
```
官方操作 → 运行总览 → 候选管理 → 回测监控 → 科学评分 → 质量门禁 → 阻断复核
```

**优化后顺序**（工作流引导）:
```
┌─ 步骤 1 ─┐  运行总览          [凭证 + 连接]
├─ 步骤 2 ─┤  候选管理          [1,247]
├─ 步骤 3 ─┤  回测监控          [4/8]
├─ 步骤 4 ─┤  科学评分          [28]
├─ 步骤 5 ─┤  质量门禁          [通过: 72%]
├─ 步骤 6 ─┤  阻断复核          [!]
├──────────┤
│  工具箱   │
├──────────┤
             官方操作             [web]
             云端快照             [25.5k]
             续跑记录             [12]
             系统配置
```

**关键变化**:
- Dashboard 提到首位（工作流入口）
- 步骤编号 1→6 自然引导用户线性前进
- "工具"区收纳非工作流操作（官方操作、云端快照、历史、配置）
- 活跃步骤自动高亮

### 3.2 顶部栏 — 上下文永不离身

```
┌──────────────────────────────────────────────────────────────┐
│ BRAIN > 候选管理                          ● 已连接  [4/8] ⏳ │
│ ← 返回                                                            │
└──────────────────────────────────────────────────────────────┘
```

**面包屑路径**：`BRAIN > 候选管理 > N1Axlk7X`
- 主路径始终显示当前位置
- 在深层视图（评分）可点击面包屑快速返回

**运行中 minibar**（仅当有活动任务时显示）：
- 显示：`⏳ 非提交验证 · 3/10 轮次 · 45% · 预计 02:30`
- 点击展开 → 完整 JobMonitor 面板（浮层，不改变当前页面）
- 任务完成 → 自动消失 + toast 通知

### 3.3 状态提升 — 跨页面共享

**当前问题**：`JobMonitor` 的 `jobId`, `running`, `status`, `events` 全在组件本地 state 中。

**解决方案**：提取 `useJobState()` hook，状态提升到 App 级别：

```tsx
// App.tsx — 全部子页面可共享
const jobState = useJobState(); // { jobId, running, status, progress, startJob, stopJob }

// TopBar 显示迷你进度
<TopBar runningJob={jobState} />

// 任何页面都可嵌入 JobMonitor（浮层模式）
{jobState.running && <FloatingJobMonitor jobState={jobState} />}
```

**效果**：
- 用户在"候选管理"页面发起验证 → 导航到"科学评分"→ 任务进度 minibar 仍在顶部栏
- 任务完成后自动 toast 通知，minibar 消失
- 不再需要在 Dashboard "守着"进度

### 3.4 导航行为修正

| 行为 | 当前 | 优化后 |
|------|------|--------|
| 从候选管理点"评分" | 跳转评分页 | 跳转评分页 |
| 从评分页"返回" | 无返回按钮，需点侧边栏 | 顶部栏显示"← 返回候选管理" |
| 返回候选管理后 | `selectedCandidate` 被清空 | 保留选中状态，回到之前位置 |
| 作业运行时导航 | JobMonitor 销毁 | minibar 在顶部栏持续显示 |

### 3.5 空状态设计

每个页面需要设计"首次到达"的空状态，目前多数页面直接显示空表格。

| 页面 | 当前空状态 | 优化后 |
|------|-----------|--------|
| 候选管理 | 空表格 "暂无候选记录" | 引导卡："还没有候选 Alpha，点击生成候选开始" + 快捷生成按钮 + 数量选择器 |
| 科学评分 | "选择候选" 提示 | 引导卡："选择一个候选来评分" + 列出最近 3 个候选的快捷入口 |
| 回测监控 | 空槽位 | 引导卡："还没有回测任务，回到候选管理选择达标候选提交回测" + 快捷跳转链接 |
| 质量门禁 | "暂无数据" | 引导卡："评分后候选会自动进入门禁检查，或手动触发质量检查" |

## 四、交互流程图

### 主流程：日常研究周期

```
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ ① 运行总览    │────→│ ② 候选管理    │────→│ ③ 回测监控    │
│ 连接+验证     │     │ 生成+筛选     │     │ 监测官方回测  │
└──────────────┘     └──────────────┘     └──────┬───────┘
                                                  │
               ┌──────────────────────────────────┘
               ↓
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│ ⑥ 阻断复核    │←────│ ⑤ 质量门禁    │←────│ ④ 科学评分    │
│ 提交前最终检查 │     │ 达标+警告列表 │     │ 指标+归因     │
└──────────────┘     └──────────────┘     └──────────────┘
```

**子路径**（可从任意步骤进入）：
- 官方操作：任何时候刷新上下文 → 回到步骤 1
- 系统配置：任何时候修改参数 → 回到当前步骤

### 评分子流程

```
候选管理（第2步）
  │
  │ 点击"评分"按钮
  ↓
科学评分（第4步）          ← 如果候选未评分，自动发起评分请求
  │                         顶部栏：← 返回候选管理 | N1Axlk7X
  │ 查看评分后
  ├── 满意 → 侧边栏点击"质量门禁"（第5步）
  └── 不满意 → 点击"← 返回候选管理"
```

### 作业运行跟踪

```
任意页面                  顶部栏始终显示
  │                     ┌──────────────────────┐
  │ 发起作业             │ ⏳ 验证中 · 45% · 2:30 │  ← 可点击展开
  ├── 导航到其他页面     └──────────────────────┘
  │                     进度 minibar 持续更新
  ├── 作业完成
  │                     Toast: "验证已完成 · Val #2048"
  └── 查看结果
                        点击 toast → 跳转到运行总览查看结果
```

### 1.2 核心发现 (深度验证)
1. **web.py 是 1135 行的 God Object** (P0): 所有 HTTP 路由 (~40 endpoints)、会话管理 (inline stubs)、异步作业管理 (ASYNC_JOBS dict)、SSE 流、数据读取 (_read_jsonl_tail) 全在一个文件中。Handler 类定义在 dispatch 函数下方，形成双重路由机制
2. **评分系统架构成熟** (P1): 三层评分架构 (Prior 30% + Empirical 45% + Checklist 25%) 已实现。`scoring/gates.py` 实现零偏差门禁验证 (`OFFICIAL_HARD_GATE_NAMES`)。`scoring/attribution.py` 实现多维归因树 (`build_attribution_tree()`)。`_ratio()` 函数设计合理，Sharpe 使用 `_num()` 而非 `_ratio()`，边界条件无实际风险
3. **本地回测引擎完善** (P2): `local_backtest_engine.py` (1139行) 支持 ~20 FASTEXPR 算子、合成数据提供、组合构建、11 项标准指标。Fitness 公式与 BRAIN 官方一致: `Sharpe × √(|Returns| / max(Turnover, 0.125))`
4. **知识库三层架构** (P2): `knowledge_base.py` (632行) 实现 rules/findings/failures 三层结构，支持从研究记忆自动提取、约束注入到生成器、模式匹配查询
5. **前端全面中文化已完成**: 15 个 React 组件已中文化，状态卡导航模式已实现
6. **Pipeline Mixin 模式**: `AlphaResearchPipeline` 通过 10 个 Mixin 类拆分
7. **UX 引导流水线完善**: `ux/guided_pipeline.py` (467行) 实现 10 阶段流程引导、检查点/恢复、运行历史、可操作错误消息
8. **Web HTTP 处理器已拆分**: `web_http_handler.py` (220行) 已从 web.py 部分提取，但仍需完善
9. **生成器架构合理**: `generator.py` (796行) 实现经验引导生成、观测性多样性增强、知识约束注入、22 个模板骨架

### 1.3 紧急行动项 (已验证)
1. **P0-1: web.py God Object 拆分** — 1135 行单文件包含 40+ API 路由、inline session stubs、ASYNC_JOBS 管理、SSE 流、数据读取，违反 SRP
2. ~~**P0-2: `_ratio()` 函数边界条件**~~ — **误诊**: Sharpe 使用 `_num()` 而非 `_ratio()`，`_ratio()` 设计合理且有测试覆盖
3. ~~**P1-1: `_score_history` 内存泄漏**~~ — **已修复**: 已有 `_MAX_SCORE_HISTORY_PER_ALPHA = 100` 和 `_MAX_SCORE_HISTORY_TOTAL_ENTRIES = 10_000` 限制
4. ~~**P1-2: ASYNC_JOBS 无清理机制**~~ — **已修复**: 添加了 `_prune_async_jobs()` 定时清理机制 (TTL 1小时，最大 200 条)
5. **P1-3: session stubs 安全风险** — web.py:44-52 的 inline session stubs 是空实现，无实际安全验证
6. ~~**P1-4: CORS 过于宽松**~~ — **已修复**: CORS 策略已收紧为 localhost 限制，添加了安全头

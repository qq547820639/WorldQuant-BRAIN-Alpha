## 1. 执行摘要

BRAIN Alpha Ops 是一个面向量化研究者的本地 Web 控制台，连接 WorldQuant BRAIN API，支持 Alpha 发现、评分、校验和提交审核。当前产品已完成 UI 重构（"Terminal Precision" 设计系统），通过了一次 E2E 用户测试和多次 UX 评估。

### 当前用户满意度基线

| 维度 | 当前评分 | 目标 |
|------|----------|------|
| 桌面端可用性 | **3.7/5** | 4.2/5 |
| 移动端可用性 | **2.8/5** | 3.8/5 |
| 无障碍合规 | **2.4/5 (WCAG AA)** | 4.0/5 |
| 首屏 JS | 203KB（↓30%） | <180KB |

### 研究发现摘要

基于已有的 UX 评估、E2E 测试、无障碍审计和代码审查共 **47 份研究文档**的综合分析，识别出：

- **15 项明确用户体验痛点**（P0 级 2 项，P1 级 7 项，P2 级 6 项）
- **3 类核心用户画像**（新手研究员、资深策略师、运维管理员）
- **7 个关键流失节点**贯穿从首次进入到提交成功的完整流程

## 2. A 部分：用户研究计划

### 2.1 研究目标

| 编号 | 核心研究问题 | 研究类型 | 业务影响 |
|------|-------------|----------|----------|
| RQ-1 | 量化研究员发现和提交 Alpha 的完整工作流是什么？当前工具在哪些环节造成最大摩擦？ | 定性 | 优化核心转化漏斗，减少流失 |
| RQ-2 | 新手与专家的行为模式有何差异？新手首次成功提交需要多长时间？ | 混合 | 差异化 onboarding 和功能暴露策略 |
| RQ-3 | 长任务（云端同步、批量检查）期间用户如何监控和决策？当前进度反馈是否足够？ | 定性+定量 | 提升长任务完成率和用户信心 |
| RQ-4 | 移动端使用场景是什么？哪些功能在移动端确实需要？ | 定性 | 确定移动端投入优先级 |
| RQ-5 | 无障碍需求用户（键盘操作、读屏软件）能否独立完成核心任务？ | 可用性测试 | WCAG 2.1 AA 合规 |
| RQ-6 | 提交审核路径的概念模型是否清晰？用户是否知道"达标"与"可提交"的区别？ | 混合 | 减少误操作和提交失败 |
| RQ-7 | 错误恢复体验如何？云端同步超时、提交失败后用户能否独立恢复？ | 定性 | 减少支持请求量 |

### 2.2 研究方法设计

#### 方法矩阵

```
研究阶段    │ 定性                          │ 定量
───────────┼──────────────────────────────┼─────────────────────────
Phase 1    │ 情境访谈 (n=12)               │ 线上问卷 (n=80+)
探索       │ 日记研究 (n=8, 5天)           │ 当前行为数据分析
───────────┼──────────────────────────────┼─────────────────────────
Phase 2    │ 可用性测试 (n=15, 3轮)        │ A/B 测试
验证       │ 认知走查 (n=5 专家)           │ SUS 量表 (n=30+)
───────────┼──────────────────────────────┼─────────────────────────
Phase 3    │ 满意度深度访谈 (n=10)         │ NPS 追踪
评估       │ 无障碍测试 (n=5, 含残障用户) │ 任务完成率/时长
```

#### Phase 1：探索性研究（第 1-2 周）

**方法 1：情境访谈**
- **样本**：12 名量化研究员（新手 4 名、中级 5 名、资深 3 名）
- **时长**：每人 60 分钟，远程进行
- **招募渠道**：WorldQuant BRAIN 社区、量化研究论坛、内部用户库
- **关键脚本主题**：
  1. 描述你最近一次 Alpha 从构思到提交的完整过程
  2. 在这个过程中，哪个环节让你感到最沮丧？
  3. 如果工具可以自动帮你做一件事，你最希望是什么？
  4. 你用什么设备查看 Alpha 状态？在什么场景下？
  5. 当云端同步失败或超时时，你通常怎么做？

**方法 2：日记研究**
- **样本**：8 名活跃用户
- **时长**：连续 5 个工作日
- **记录内容**：每次操作的工具、任务、耗时、挫折点、成功感
- **工具**：结构化日记模板（Google Form / Notion）

**方法 3：线上问卷**
- **目标样本量**：80+ 份有效问卷
- **关键问题**：
  - 使用频率（每日/每周/每月）
  - 主要使用场景和阶段
  - 功能满意度评分（5 分量表）
  - 核心痛点开放式问题
  - SUS（系统可用性量表）10 题标准版
  - NPS 推荐意愿

#### Phase 2：验证性研究（第 3-4 周）

**方法 4：可用性测试**
- **样本**：15 名参与者（5 名/轮，共 3 轮迭代）
- **测试环境**：受控远程测试，录制屏幕+声音
- **核心任务场景**：

```
任务 1：首次连接与云端同步
  - 打开控制台
  - 输入凭据并测试连接
  - 触发云端同步并等待完成
  - 成功标准：云端 Alpha 数据显示在表格中
  - 观察重点：连接状态理解、同步进度感知、超时恢复能力

任务 2：候选发现与筛选
  - 从仪表盘导航到候选发现
  - 开始生产搜索
  - 使用关键词筛选候选 Alpha
  - 成功标准：找到并选择目标候选
  - 观察重点：导航效率、筛选可用性、结果可读性

任务 3：评分与校验
  - 选择一个候选 Alpha
  - 查看评分详情和门禁状态
  - 理解"达标"与"可提交"的区别
  - 成功标准：正确解释评分结果并判断下一步
  - 观察重点：信息架构理解、概念模型清晰度

任务 4：提交审核
  - 选择可提交 Alpha
  - 运行批量检查
  - 查看检查结果和阻断项
  - 成功标准：正确识别哪些 Alpha 可提交及原因
  - 观察重点：阻断项理解、失败恢复路径

任务 5：移动端监控（可选）
  - 在手机上打开控制台
  - 查看当前运行状态
  - 找到云端 Alpha 数量
  - 成功标准：在移动端完成核心监控
  - 观察重点：移动端布局适配、触控目标大小
```

**方法 5：认知走查**
- **参与者**：5 名 UX 专家（外部+内部）
- **走查维度**：
  - 可学习性（新用户能否独立完成首次任务）
  - 效率（专家用户能否高效完成高频任务）
  - 防错性（系统如何预防和恢复错误）
  - 无障碍性（键盘/读屏用户能否完成核心任务）

#### Phase 3：评估性研究（第 5-6 周）

**方法 6：无障碍测试**
- **样本**：5 名参与者（含 2 名读屏软件用户、2 名键盘操作用户、1 名色觉障碍用户）
- **测试内容**：
  1. 仅键盘完成任务 1-4（Tab/Enter/Space/Esc 导航）
  2. 使用 NVDA/VoiceOver 完成相同任务
  3. 验证所有状态变化有语音反馈
  4. 验证 Toast、进度条、弹窗的 ARIA 语义
  5. 验证色彩对比度和非颜色信息传达

### 2.4 数据分析计划

#### 定性数据分析

1. **主题分析**：对访谈转录稿和可用性测试录像进行编码
   - 开放编码 → 轴向编码 → 选择性编码
   - 使用亲和图（Affinity Diagram）组织发现
   - 交叉验证：至少 2 名研究者独立编码，计算评分者间信度

2. **行为模式提取**：
   - 用户旅程地图（当前态 + 理想态）
   - 流程图分析（标注实际路径与预期路径的偏差）
   - 错误模式分类（类型、频率、恢复路径）

#### 定量数据分析

1. **可用性测试指标**：
   - 任务完成率（目标 >85%）
   - 任务完成时间（对比基线）
   - 错误次数（关键错误 vs 非关键错误）
   - 单次故障可恢复率

2. **问卷分析**：
   - SUS 总分和分项分析
   - NPS 计算和分群
   - 满意度与行为指标的相关性分析
   - 不同用户群的差异检验（ANOVA / t-test）

3. **行为数据分析**（如有埋点）：
   - 功能使用频率和序列
   - 流失漏斗分析
   - 会话时长和深度

                    "调用哪步?"                                              "看什么?"

### 5.2 各阶段关键发现

#### 阶段 1: 连接与认证

- **优势**：连接测试即时反馈明确（"连接成功"）、凭据字段自动脱敏
- **问题**：连接成功后顶部状态栏可能仍然显示 `offline --`（P1-3），用户困惑
- **建议**：状态栏区分 "API 认证" 和 "云端数据同步" 两个独立状态

#### 阶段 2: 云端同步

- **优势**：进度条存在、冲突操作被正确锁定
- **问题**：同步长时间停在 0%，无细粒度进度（P0-1）、无重试/取消按钮
- **建议**：增加分阶段进度（认证→拉取字段→拉取Alpha→缓存）、添加取消和重试按钮

#### 阶段 3: 候选发现

- **优势**：筛选功能完整、真实数据表格
- **问题**：新用户首次进入被配置面板淹没（P1-1）、空态缺少上下文快捷操作
- **建议**：新手模式默认折叠高级配置、空态增加"开始生产搜索"引导按钮

#### 阶段 4: 评分与校验

- **优势**：评分信息完整（Sharpe、Fitness、Turnover等）
- **问题**：达标/可提交概念边界模糊（P1-5）
- **建议**：增加清晰的状态流转图和概念解释提示

#### 阶段 5: 批量检查

- **优势**：检查项有中文标签和建议
- **问题**：批量失败时缺少逐项修复（P1-6）、图表空态显示"Chart.js未加载"（P1-7）
- **建议**：检查结果增加逐项重试、图表空态改为用户友好的占位文案

#### 阶段 6: 提交审核

- **优势**：提交按钮正确禁用（安全）、阻断项明确列出
- **问题**：缺少逐项修复建议（P1-6）
- **建议**：每个阻断项附带具体修复指导

## 6. E 部分：优先级建议与行动路线

### 6.1 优先级矩阵

采用 **影响 × 频率 × 修复成本** 三维评分：

```
优先级 = (影响得分 × 频率得分) / 修复成本得分

影响:  阻断任务=5  严重摩擦=3  体验不佳=1
频率:  每次=5      每日=3      偶尔=1
成本:  低(<1天)=3  中(1-3天)=2  高(>3天)=1
```

### 6.2 短期行动（第 1-2 周）

1. **云端同步恢复能力** (P0-1) — 最高优先级
   - 增加 "取消同步" 按钮（带二次确认）
   - 增加 "重试同步" 按钮
   - 在超时消息旁添加 "查看日志" 链接
   - 显示当前同步阶段（认证→拉取字段→拉取Alpha→缓存）

2. **顶部连接状态修复** (P1-3)
   - 区分两个独立状态指示器：认证状态 + 数据同步状态
   - 成功连接后立即更新认证状态为 ✅
   - 同步状态独立显示

3. **图表空态文案** (P1-7)
   - 将 "Chart.js 未加载，当前视图暂无可绘制数据" 改为
   - "图表视图暂不可用，您可以在表格视图中查看完整数据"

### 6.3 中期行动（第 3-6 周）

4. **新手引导模式** (P1-1)
   - 检测用户首次访问，默认折叠高级配置区
   - 增加分步引导：连接 → 同步 → 搜索 → 查看结果
   - 关键配置项添加 "推荐值" 标记

5. **达标/可提交概念澄清** (P1-5)
   - 增加状态流转可视化图
   - 在关键操作旁加入问号提示（hover 显示说明）
   - 在 "可提交" 标签旁显示通过条件清单

6. **状态卡优先级分层** (P1-4)
   - 状态卡分为 3 层：核心流程（4 张）、辅助监控（6 张）、数据快照（6 张）
   - 默认展开核心流程，其他折叠
   - 专家用户可自定义显示/隐藏

### 6.4 长期行动（第 7 周及以后）

7. **移动端响应式重构** (P1-2)
   - 移动端首屏改为：顶部状态栏 → 核心结果区 → 可滚动配置
   - 增加底部 Tab 导航快速切换核心视图
   - 按钮统一提升至 44px 最小触控

8. **提交失败逐项管理** (P1-6)
   - 失败列表增加错误类型筛选
   - 每个失败项增加 "修复建议" 和 "单项重试"
   - 支持按错误类型批量重试

9. **无障碍全面合规** (P0-2, P2-1~P2-6)
   - 完整的 ARIA 语义补充
   - 键盘导航完整覆盖
   - WCAG 2.1 AA 合规验证

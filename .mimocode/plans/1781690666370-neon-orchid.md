# Web层双分发整合计划

## 审查范围
82个web_*.py文件（~23,000行）+ React前端35个组件

---

## 现状分析

### 双分发系统
| 系统 | 文件 | 行数 | 路由数 | 状态 |
|------|------|------|--------|------|
| 新dispatch | web_handler_dispatch.py | 995 | GET:35, POST:15 | 活跃 |
| 旧legacy | web_routes.py | 936 | GET:20+, POST:10+ | 共存 |
| 集成层 | web/__init__.py | 1089 | 路由分发 | 整合两套系统 |

### 文件分类（82个web_*.py）

| 类别 | 文件数 | 总行数 | 说明 |
|------|--------|--------|------|
| Core Dispatch | 3 | 3,020 | handler_dispatch + routes + __init__ |
| Context & State | 6 | 1,800 | dispatch_context + state_contract + session等 |
| Candidate Operations | 17 | 8,500 | candidate_*.py（最碎片化） |
| Job Management | 4 | 1,200 | jobs + async_jobs + backtest_slots |
| Config | 3 | 900 | config + config_bindings |
| Cloud & Sync | 4 | 2,800 | cloud_*.py + sync_*.py |
| Submission | 3 | 1,200 | submission_*.py + submit_readiness |
| Scoring | 2 | 600 | scoring相关 |
| SSE | 1 | 100 | sse.py |
| Facade | 3 | 800 | facade_bindings + compat_facade + legacy_exports |
| Other | 19 | 4,500 | misc |

### 用户体验影响

**当前痛点：**
1. 路由分散在两套系统中，新功能不知该加在哪
2. 错误响应格式不一致（部分用`_error_response`，部分直接返回dict）
3. 部分端点响应慢（重复逻辑、多次JSON解析）
4. 开发者困惑：82个文件不知从何入手

**整合后收益：**
1. 统一路由注册，新功能只需加一处
2. 统一错误处理和响应格式
3. 减少重复代码，提升响应速度
4. 清晰的模块边界，降低维护成本

- `brain_alpha_ops/web_candidate_audit.py` (510L)
- `brain_alpha_ops/web_candidate_simulation_state.py` (497L)
- `brain_alpha_ops/web_candidate_bindings.py` (584L)
- `brain_alpha_ops/web_candidate_workflow.py` (336L)
- `brain_alpha_ops/web_candidate_check_evidence.py` (344L)
- `brain_alpha_ops/web_candidate_payloads.py` (353L)
- `brain_alpha_ops/web_candidate_lifecycle_risk.py` (339L)
- `brain_alpha_ops/web_candidate_selection.py` (336L)
- `brain_alpha_ops/web_candidate_simulation_failures.py` (329L)
- `brain_alpha_ops/web_candidate_optimization_explainability.py` (326L)
- `brain_alpha_ops/web_candidate_generation_summary.py` (323L)

**整合方案：**
```
web_candidates/                    # 新目录
├── __init__.py                    # 导出公共API
├── simulation.py                  # 模拟相关（simulation + simulation_state + failures）
├── optimization.py                # 优化相关（optimization + explainability）
├── generation.py                  # 生成相关（generation + summary）
├── lifecycle.py                   # 生命周期（decisions + audit + lifecycle_risk + workflow）
├── payloads.py                    # 数据载荷（payloads + check_evidence）
└── bindings.py                    # 绑定层（保留向后兼容）
```

**用户体验影响：**
- 候选操作响应速度提升（减少模块加载开销）
- 错误信息更一致（统一错误处理）
- 开发者体验改善（文件数从17减至7）

### Phase 2: 路由统一

**目标：** 消除双分发，统一到新dispatch系统

**步骤：**
1. 识别web_routes.py中仍在使用的路由
2. 将这些路由迁移到web_handler_dispatch.py
3. 删除web_routes.py中的冗余代码
4. 更新web/__init__.py的分发逻辑

**关键文件：**
- `brain_alpha_ops/web_handler_dispatch.py` (995L)
- `brain_alpha_ops/web_routes.py` (936L)
- `brain_alpha_ops/web/__init__.py` (1089L)

**用户体验影响：**
- 统一的API行为（所有路由使用相同的错误处理）
- 消除"某些端点行为不同"的困惑
- 更快的响应（减少路由查找开销）

## 用户体验优化重点

### 1. 错误响应一致性
**现状：** 部分端点返回`{"ok": false, "error": "..."}`，部分返回`{"error_code": "...", "error": "..."}`

**目标：** 统一为`{"ok": bool, "error_code": str, "error": str, "data": dict}`

**影响：** 前端错误处理更简单，用户看到的错误信息更清晰

### 2. 加载状态反馈
**现状：** 部分操作无进度反馈

**目标：** 所有耗时操作（>500ms）提供SSE进度流

**影响：** 用户知道操作正在进行，不会误以为卡死

### 3. 响应时间优化
**现状：** 部分端点多次JSON解析、重复计算

**目标：** 关键路径响应时间<200ms

**影响：** 界面更流畅，用户操作更即时

### 4. API文档一致性
**现状：** 无统一API文档

**目标：** 从代码生成OpenAPI spec

**影响：** 开发者体验改善，前端调用更准确

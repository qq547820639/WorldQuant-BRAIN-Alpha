# 2026-06-12 — BRAIN Alpha Ops 全面深度静态分析

## 任务

应 PAN 要求,基于项目源码做"忽略历史文档"的全面深度静态分析。

## 关键发现概览(完整内容见对话回复)

### 1. 真实 bug:`web_http_handler.py:94-112` 的 `_send_json` 双重 `end_headers`

`web_http_handler.py` 工厂创建的 `Handler` 类,在 `_send_json()` 方法里:

- 第一次 `self.end_headers()`(第 103 行)
- 之后又调用 `self.send_header()` 三次(第 105-110 行)
- 然后再 `self._send_security_headers()`(第 111 行)
- 然后又 `self.end_headers()`(第 112 行)

Python `BaseHTTPRequestHandler` 不允许在 `end_headers()` 后再调用 `send_header`/`end_headers`。当前该路径未被使用(实际 `dispatch_post` 走的是 `web/__init__.py:707` 的内联 `_send_json`,它**没有**这个 bug),所以现状是 latent bug — 但任何把 handler 工厂换为主分发器的改动都会瞬间触发。

### 2. 并行双 Handler 实现的实际行为

虽然 `web_http_handler.py` 有 bug,但 `web/__init__.py:631` 的 `Handler` 内联实现是**实际生产**的:
- 它**正确**地按顺序: `send_response` → `send_header(Content-Type)` → `send_header(Content-Length)` → `_send_security_headers` → `extra_headers` → `end_headers` → `write`
- **没有** 注入 CSP(只是 `_send_security_headers` 只发 X-Content-Type-Options / X-Frame-Options / Referrer-Policy)
- 而 `web_http_handler.py:270-277` 的 `_send_security_headers` 才有 CSP

因此:**当前线上 handler 不发 CSP**。文档承诺的"基于 HTML 计算 SHA-256"是 `web_csp.py` 的能力,但因为 handler 没被工厂创建,这个能力在生产路径上是死的。

### 3. 提交路径的"双重防线"实际只一道

- `web/__init__.py:341-357` `_submit_disabled_payload()` 返回固定阻断
- `web/__init__.py:556-624` `dispatch_post` 14 个真实后端路由里 `/api/submit`、`/api/submit_batch` **直接**调 `_submit_disabled_payload()`
- 但 `web_submission_single.py:31` 的 `submit_candidate_payload()` 是**真实现** — 不通过 `web/__init__.py` 派发,而是 `web_handler_dispatch.py:759-768` 的 `_post_submit()` 同样返回 `REAL_SUBMIT_DISABLED_WEB_FLOW`
- **如果有人改 `web/__init__.py:341-357` 或 `web_handler_dispatch.py:759-768` 把那两行取消** —— 真提交就会重新打开
- **没有任何中心化常量** `REAL_SUBMIT_DISABLED = True` 之类把这个约束写进"不可移除的常量"

### 4. 线程守护标志不一致

- `web/__init__.py:143` `_run_generate_candidates_job` 启动用 `daemon=False`
- 这意味着 Python 进程退出时不会杀线程
- 启动器 `web_cli.py:serve()` 没有 `join()`,会留 zombie

### 5. 配置层有两套并行模型

- `brain_alpha_ops/config_models.py` 提供 `RunConfig`/`OpsConfig`/`QualityThresholds` 等 dataclass
- `brain_alpha_ops/config_schema.py`(17KB)和 `brain_alpha_ops/config/_loader.py` 用 jsonschema
- 两者并存:`config_models.py` 是真值源,`config_schema.py` 是验证镜像
- `config/__init__.py` 重新导出 18+ 符号

## 关键工程观察

- **包代码体量**:`brain_alpha_ops` 共 ~296 个 `.py` 文件、`research/` 99 个、web_*.py 21,597 行根级
- **测试体量**:`tests/` 209 文件 + 40 脚本 — 1:1 覆盖率密度合理
- **依赖**:仅 `pyyaml` / `requests` / `jsonschema` 三方;web 走 stdlib `http.server` + SSE
- **架构分层**(`.importlinter` 强制):
  - `shared/` 无 `research/web/agents` 上行依赖
  - `brain_api/` 不导入 `research/web/agents`
  - `research/` 不导入 `web/agents`
  - `config/` 不导入 `research/web/agents`
- **零硬编码真理源**:`brain_api/canonical.py` 提供 `CANONICAL_THRESHOLDS`、`CANONICAL_API_PATHS`、`SUPPORTED_*`;`compliance/redline_verifier.py` 强制六条红线

## 2026-06-09 上午: 状态持久化 + 空状态优化 (ArchitectUX)
用户追问：刷新页面/跳转模块/关闭重开会丢失运行状态吗？还有什么问题？

### 诊断结论：刷新和关闭会丢失前端运行状态
虽然后端任务容器在内存中继续运行，但前端没有任何持久化：
- **jobId** 在 React state 中 → 刷新即丢失，无法重连 SSE 和轮询
- **connectionTested** 在 React state 中 → 刷新后顶栏显示"未连接"
- **凭证** 仅在内存 → 刷新后需重新填写（安全设计，不持久化密码）
- **后端任务**继续运行但前端永远无法观察到它
- 导航到其他模块再返回：✅ 状态保持（App 级别 state 在导航中不丢失）

### 修复 1: useJobState 添加 sessionStorage 持久化 + 挂载恢复
- **useJobState.ts**: 
  - 任务启动时调用 `saveJobId(jid)` 写入 `sessionStorage`
  - 组件挂载时从 `sessionStorage` 读取 `brain_alpha_active_job_id`
  - 若找到且任务仍在运行 → 自动重连 SSE + 轮询 + 通知"已恢复正在运行的任务"
  - 若找到但任务已结束 → 显示最终结果 + 通知 + 清除记录
  - 若找不到 → 正常空白状态
  - 任务完成/失败/停止/看门狗超时 → 自动 `clearSavedJobId()`
  - 新增 `recovering` 状态暴露给 UI

### 修复 2: App.tsx 持久化 connectionTested 到 sessionStorage
- 连接测试成功后写入 `brain_alpha_connection_tested = "1"`
- App 初始化时从 sessionStorage 读取，避免每次刷新都显示"未连接"

### 修复 3: CandidateTable 空状态添加引导文案
- 新增 `EmptyState` 组件，根据 `showProductionControls` 和 `filter` 显示不同引导
- 有筛选时：提示调整或清除筛选条件
- 无筛选 + 有生产控制：显示图标 + "暂无候选记录" + 引导去运行总览启动验证
- 无筛选 + 无生产控制（嵌入视图）：引导先运行验证或从候选管理选择

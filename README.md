# brain-alpha-ops 用户操作手册

`brain-alpha-ops` 是一个运行在本机浏览器里的 WorldQuant BRAIN Alpha 操作工作台。你可以用它完成账号连接、云端同步、候选生成、结果查看、达标检查和提交前确认。

本手册面向最终用户，重点说明“怎么安装、怎么配置、怎么使用、遇到问题怎么处理”。

[截图：首页总览]

## 1. 产品简介与核心功能概述

### 1.1 产品用途

`brain-alpha-ops` 适合在本地电脑上管理 BRAIN Alpha 研究流程。它不会替你绕过官方规则，也不会默认自动提交 Alpha；它的主要作用是把复杂流程整理成可查看、可确认、可追踪的页面操作。

### 1.2 核心功能

1. **账号连接**：在本地页面输入 BRAIN 账号信息，或使用环境变量读取凭据。
2. **云端同步**：同步账号下已有 Alpha，方便识别重复和历史记录。
3. **候选生成**：根据配置生成新的 Alpha 候选。
4. **结果查看**：在表格和图表里查看候选状态、排序分和风险原因。
5. **达标检查**：对候选做提交前检查，确认是否可以继续处理。
6. **提交前确认**：只在候选通过检查后，再进入提交队列处理。

[截图：核心功能区域]

### 1.3 使用原则

1. 先同步云端数据，再生成或检查候选。
2. 先看“风险 / 原因”列，再决定下一步。
3. 保持 `auto_submit` 关闭，除非你非常确认要启用自动提交。
4. 不要把真实账号、密码、token 或 cookie 写入 README、配置文件、截图或提交记录。

## 2. 详细安装与环境配置步骤

### 2.1 准备环境

请先确认你已经准备好：

1. Python 3.10 或更高版本。
2. 一个可用的 WorldQuant BRAIN 账号。
3. 可以打开本地网页的浏览器。
4. 项目代码所在目录。

[截图：准备环境]

### 2.2 安装项目

macOS / Linux：

```bash
cd WorldQuant-BRAIN-Alpha
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install --upgrade pip
python3 -m pip install -e .
```

Windows PowerShell：

```powershell
cd WorldQuant-BRAIN-Alpha
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e .
```

[截图：安装完成]

### 2.3 配置 BRAIN 凭据

推荐使用环境变量。这样凭据不会写入配置文件。

macOS / Linux：

```bash
export BRAIN_USERNAME="your_email_here"
export BRAIN_PASSWORD="your_password_here"
```

如果你使用 token：

```bash
export BRAIN_TOKEN="your_token"
```

Windows PowerShell：

```powershell
$env:BRAIN_USERNAME="your_email_here"
$env:BRAIN_PASSWORD="your_password_here"
```

如果你使用 token：

```powershell
$env:BRAIN_TOKEN="your_token"
```

[截图：配置凭据]

### 2.4 检查配置文件

默认配置文件是 [config/run_config.json](config/run_config.json)。第一次使用时，重点看这些字段：

| 字段 | 建议值 | 用途 |
|---|---|---|
| `environment` | `production` | 使用正式 BRAIN 环境 |
| `auto_submit` | `false` | 默认不自动提交 |
| `web.host` | `127.0.0.1` | 只允许本机访问 |
| `web.port` | `8765` | 本地网页端口 |
| `ops.storage_dir` | `data` | 保存本地运行数据 |

修改配置后，保存文件并重新启动 Web 控制台。

[截图：配置文件关键字段]

### 2.5 启动 Web 控制台

在项目目录中运行：

```bash
python3 launch_web.py
```

Windows PowerShell 中也可以运行：

```powershell
python launch_web.py
```

然后打开浏览器访问：

```text
http://127.0.0.1:8765
```

[截图：浏览器打开控制台]

## 3. 核心功能使用指南

### 3.1 流程一：连接账号

1. 打开 `http://127.0.0.1:8765`。
2. 找到页面中的“连接与身份”区域。
3. 如果你已经设置环境变量，确认页面能读取或使用当前凭据。
4. 如果没有设置环境变量，可以在页面中临时输入账号信息。
5. 确认运行环境显示为 production。

[截图：操作步骤 3.1 连接账号]

### 3.2 流程二：同步云端数据

1. 在页面中找到“云端数据”或“同步云端数据”按钮。
2. 选择同步范围；第一次使用建议选择较短范围。
3. 点击“同步云端数据”。
4. 等待进度完成。
5. 查看页面是否显示云端 Alpha 数量或同步结果。

[截图：操作步骤 3.2 同步云端数据]

### 3.3 流程三：开始生产搜索

1. 确认账号已连接。
2. 确认云端数据已同步。
3. 保持默认市场与回测参数。
4. 点击“开始生产搜索”。
5. 等待候选列表出现新结果。
6. 查看每条候选的状态、排序分和风险原因。

[截图：操作步骤 3.3 开始生产搜索]

### 3.4 流程四：查看候选结果

1. 切换到候选列表或表格视图。
2. 优先查看“状态”列。
3. 再查看“排序分”列，找到值得继续处理的候选。
4. 查看“风险 / 原因”列，判断是否有阻断原因。
5. 如果候选不达标，先不要提交。

[截图：操作步骤 3.4 查看候选结果]

### 3.5 流程五：执行达标检查

1. 找到进入达标检查的入口。
2. 选择要检查的候选。
3. 点击“检查”。
4. 等待检查完成。
5. 查看通过数量、失败数量和失败原因。
6. 只把通过检查的候选放入后续处理。

[截图：操作步骤 3.5 执行达标检查]

### 3.6 流程六：处理提交队列

1. 打开“提交队列”或“可提交”视图。
2. 确认候选已经通过检查。
3. 再次查看“风险 / 原因”列。
4. 勾选你要处理的 Alpha。
5. 点击“提交勾选”。
6. 如果按钮不可用，先根据页面提示处理问题。

[截图：操作步骤 3.6 处理提交队列]

### 3.7 流程七：只查看结果，不提交

1. 打开 Web 控制台。
2. 同步云端数据。
3. 查看候选列表和图表。
4. 不勾选提交项。
5. 不开启自动提交。
6. 需要继续处理时，再回到达标检查流程。

[截图：操作步骤 3.7 只查看结果]

## 4. 常见问题排查与解决方案

### 4.1 Web 页面打不开

可能原因：

1. Web 控制台没有启动。
2. 端口被占用。
3. 浏览器地址输入错误。

解决步骤：

1. 回到终端，确认 `python3 launch_web.py` 仍在运行。
2. 在浏览器输入 `http://127.0.0.1:8765`。
3. 如果仍打不开，修改 `config/run_config.json` 里的 `web.port`，例如改为 `8766`。
4. 重新启动 Web 控制台。

[截图：问题 4.1 页面打不开]

### 4.2 页面显示未连接

可能原因：

1. 账号或密码错误。
2. token 过期。
3. 环境变量没有生效。
4. 网络无法访问 BRAIN。

解决步骤：

1. 重新检查 `BRAIN_USERNAME` 和 `BRAIN_PASSWORD`。
2. 如果使用 token，重新设置 `BRAIN_TOKEN`。
3. 关闭当前终端，重新打开并设置环境变量。
4. 回到页面重新点击同步或连接相关按钮。

[截图：问题 4.2 未连接状态]

### 4.3 同步云端数据失败

可能原因：

1. 凭据错误。
2. BRAIN 服务暂时不可用。
3. 操作太频繁。
4. 网络不稳定。

解决步骤：

1. 先确认账号能正常登录 BRAIN。
2. 等几分钟后重试。
3. 缩小同步范围。
4. 不要连续快速点击同步按钮。

[截图：问题 4.3 同步失败]

### 4.4 没有生成候选

可能原因：

1. 云端数据还没同步。
2. 参数设置过严。
3. 搜索任务还在启动。
4. 当前账号或网络状态异常。

解决步骤：

1. 先完成云端同步。
2. 使用默认参数重新开始生产搜索。
3. 等待一段时间后再查看候选列表。
4. 查看页面提示的风险或错误原因。

[截图：问题 4.4 没有候选]

### 4.5 “检查”按钮不可用

可能原因：

1. 没有可检查候选。
2. 另一个任务正在运行。
3. 候选状态还没有到达检查阶段。

解决步骤：

1. 等当前任务结束。
2. 查看候选状态。
3. 先完成生产搜索或云端同步。
4. 再回到达标检查入口。

[截图：问题 4.5 检查按钮不可用]

### 4.6 “提交勾选”按钮不可用

可能原因：

1. 没有勾选候选。
2. 候选没有通过检查。
3. 页面发现阻断风险。
4. 提交任务正在处理中。

解决步骤：

1. 确认候选已经通过检查。
2. 勾选要处理的 Alpha。
3. 查看“风险 / 原因”列。
4. 等当前任务完成后再试。

[截图：问题 4.6 提交按钮不可用]

### 4.7 配置文件报错

可能原因：

1. JSON 格式写错。
2. 端口不是有效数字。
3. 路径或字段名称写错。

解决步骤：

1. 打开 [config/run_config.json](config/run_config.json)。
2. 检查最近修改过的字段。
3. 确认引号、逗号和括号完整。
4. 保存后重新启动 Web 控制台。

[截图：问题 4.7 配置文件报错]

### 4.8 担心误提交

建议做法：

1. 确认 `auto_submit` 是 `false`。
2. 只在“可提交”视图中处理通过检查的候选。
3. 每次提交前都查看“风险 / 原因”列。
4. 不确定时，不要点击提交按钮。

[截图：问题 4.8 提交前确认]
